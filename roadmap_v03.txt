Work Breakdown Structure (WBS) - Phase 10: Creator Workflow
Objective: Transform Vibana from a standard storefront into a Multi-Role Platform where external designers can pitch artwork, and admins can approve and publish those designs.

Phase 10.1: Database Architecture & Roles -- Done

Create the DesignSubmission database model to hold pending artwork.

Define the submission statuses (Pending, Approved, Rejected).

Configure Django User Groups to separate standard "Customers" from "Designers."

Phase 10.2: The Creator Portal (Frontend) -- Done

Build a secure dashboard exclusively for logged-in Designers.

Create the upload form for them to submit new artwork and descriptions.

Build a status-tracking grid so they can see if their work was approved or rejected.

Phase 10.3: The Admin Approval Pipeline -- Done

Create a custom queue in the Admin portal for you to review pending submissions.

Build the "Approve" logic: clicking a button automatically duplicates their submission data into a live Product on the storefront.

Wire up notification UI/messages for the designer.

Objective: Decouple the monolithic store application into three distinct, single-responsibility applications (Store, Creator, Dashboard) and establish a role-specific UI template hierarchy.

Phase 11.1: The Foundation  -- Done

Create the feature/architecture-refactor branch.

Initialize the new Django apps (creator and dashboard).

Register the new apps in your global settings.py.

Phase 11.2: Backend Extraction & Decoupling -- Done

Extract the Creator Portal logic (views, forms, urls) from store and migrate it to the creator app.

Extract the Admin/Staff logic (views, urls, invoice generation) and migrate it to the dashboard app.

Update all internal Python import statements to point to the new locations.

Phase 11.3: Template Hierarchy (Frontend)

Split the monolithic base.html into base_store.html (B2C) and base_creator.html (B2B).

Override Django's built-in admin/base_site.html to inject Vibana's custom branding into the admin portal.

Update all HTML {% extends %} tags to use the new architecture.

Phase 11.4: Global Routing & Testing

Update the master core/urls.py to route traffic securely to the three separate apps.

Perform local regression testing to ensure no broken links or missing static assets.
